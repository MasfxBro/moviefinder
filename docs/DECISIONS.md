## Locked decisions
| ID | Decision | Why |
|---|---|---|
| D-01 | Product is search/discovery with outbound links only. No hosting/streaming/downloading of video. | Legal safety and light infrastructure. |
| D-02 | Stack: PHP 8.5, Laravel 13, MySQL 8.4 LTS, Blade + Tailwind + Alpine, Vite, Pest, Pint (newest supported versions, D-43). | Matches the certification tooling (web server + DB server) and is secure by default. |
| D-03 | Roles: `admin`, `user` (stored). The plan (Free, Plus or Pro) is derived from an active subscription or a manual grant row, never stored as a flag on the user. | A stored plan flag goes stale when a subscription ends. |
| D-04 | Quota: AI limits per plan (D-44): units per day, Smart searches per day, AI web clip searches per period, plus the AI budget guard (D-45). Daily reset at 00:00 Asia/Jakarta. Admin editable in settings. Global daily cap exists. | Predictable cost, fair limits. |
| D-05 | Catalog is a permanent local table (title metadata from TMDB). Seeded with popular titles; grows by lazy import when a title is opened/verified. TMDB-derived fields are refreshed so none is older than 150 days. | User wants titles to persist; TMDB terms are reported to limit cache age (verify before launch). |
| D-06 | DB stays light: no video/images/subtitles/dialogue; images served from TMDB CDN by path; short-lived data in the cache store, not the DB. | Fast, cheap site. |
| D-07 | ClipFinder chain: curated links -> stored resolved links -> AI web search (Gemini + Google Search) -> "search on YouTube" link. The AI does the searching and understanding; our code validates every link and a judge step scores relevance. A YouTube Data API driver exists but is disabled by default. | The AI finds real videos that match the user's intent; unverified links never reach users; no YouTube API quota needed. |
| D-08 | Preview: YouTube embeds only, click-to-load, limited to 60 seconds (`end = start + 60`) with the `end` parameter; when it ends the player is removed and a button opens the original video on its platform. Other platforms (TikTok, Instagram, X, Facebook, Vimeo, Dailymotion) are allowed as link-out results from an allow-list. | The 60-second limit can only be enforced on YouTube's player; other embeds add tracking and weight. |
| D-09 | Channel policy: allowlist. Official/trusted channels may be embedded. Unknown channels are link-out only with an "Unverified source" label. Blocked channels never appear. | Reduces copyright risk. |
| D-10 | AI chat memory lives server-side in cache with a TTL, tied to a conversation id kept in page memory. Leaving the chat discards it. If the chat has at least one message, warn before leaving. Empty chat leaves freely. | Matches the required UX; no chat logs in DB. |
| D-11 | If a title is not found locally or in TMDB: show "We could not find that title yet" and a button to the request page. Admin reviews requests and adds the data (TMDB import or manual create). | Required UX. |
| D-12 | Billing: Midtrans. The Subscription API (card and GoPay tokenization) gives monthly auto-renew; every other method is a one-time 30-day payment (D-46). Webhook-driven, 3-day grace, cancel keeps access until period end. | Netflix-style behaviour for card and GoPay without storing card data, and wide payment choice for everyone else. |
| D-14 | UI language is English: formal, standard English in plain words, no contractions (D-48). AI replies follow the user's language (English or Indonesian). Code, comments, commit messages and docs are English. | Owner requirement. |
| D-15 | Theme: dark, minimal, iOS-like. Tokens in DESIGN_SYSTEM.md; Figma refines them later. | Required. |
| D-16 | Security baseline in SECURITY.md. Admin accounts must use TOTP 2FA. | Required "strict security". |
| D-17 | Registration requires an "I am 18 or older" confirmation. Adult titles excluded. | Content suitability and data-protection caution. |
| D-22 | The app uses its own Gemini key. Keys used by the developer's coding tools are never used by the app. | Quota isolation, no key leaks. |
| D-23 | Search history kept 90 days, user can clear it. AI conversation content is not stored. | Privacy. |
| D-24 | Timezone: the framework timezone is UTC (`APP_TIMEZONE=UTC`), so timestamps are stored in UTC. Business rules (the daily AI quota reset at 00:00, daily reports, "today") use `BUSINESS_TIMEZONE=Asia/Jakarta` through `config('app.business_timezone')`. | Consistent daily reset. Setting `APP_TIMEZONE` to Asia/Jakarta would store Jakarta time, contradicting the UTC storage rule. |
| D-25 | The admin area has its own login on a secret URL (`ADMIN_PATH`), its own guard, mandatory 2FA, optional IP allow-list, 404 for outsiders. Admin accounts cannot use the public login. | Smaller attack surface, separation of duties. |
| D-26 | Admin manages everything: titles (create manual / import / edit / hide / delete), requests, missed searches, clip links, channels, reports, feedback, users, subscriptions, AI usage, settings, announcements, audit log, system health. Every web entity has an admin counterpart (coverage matrix in FEATURES.md F-17). | The owner monitors and runs the whole product. |
| D-27 | Manual titles are allowed (`source=manual`) with an admin-uploaded poster (re-encoded small WebP on disk). | Titles TMDB lacks; full CRUD. |
| D-28 | Feedback ("critique and suggestions") feature for verified users with an admin inbox. | Required. |
| D-29 | Continuity: zero-downtime releases (symlink swap), backward-compatible migrations, admin-driven settings and feature flags, graceful degradation, maintenance mode only as a last resort. | Users must not be disturbed by changes or maintenance. |
| D-30 | Responsive and interactive UI is a requirement of every task (DESIGN_SYSTEM.md section 10). | Required. |
| D-31 | Not-found search terms are aggregated without user ids (`search_misses`) to show the admin what to add. | Data-driven growth, privacy-safe. |
| D-32 | Cost principle: development, demo and first production phase cost Rp0. Only free tiers. No paid dependency without the owner's approval. Real payments stay off until launch gates pass, which also keeps TMDB usage non-commercial. | Owner requirement. |
| D-33 | MovieFinder is a listing/search site, not a viewing site. The only playback is the 60-second clip preview. | Owner requirement and legal posture. |
| D-34 | Database is MySQL 8.4 LTS, the long-term-support line (MySQL 8.0 is at or past end of life and 9.x is a short-support innovation track; check the MySQL lifecycle page before changing). PostgreSQL was considered at the owner's request and not chosen for now. Note: PostgreSQL also needs a running database server; it is not serverless. Revisit after the LSP assessment. | The LSP environment is a web server plus MySQL (Laragon/XAMPP). Switching would need a different full-text search (tsvector or trigram), different enum/json handling, `pg_dump` backups and the `pdo_pgsql` extension: more risk in a short window. |
| D-35 | Guest access: guests see only the landing page at `/`, `/pricing`, the legal pages (`/terms`, `/privacy`, `/copyright`, `/about`) and the auth pages (plus the signature-verified payment webhook, which is not a page). Everything else (browse, search, title detail, AI, watchlist, history, requests, feedback, account) requires login, and guests are redirected to the login page and returned afterwards. This REPLACES the earlier rule that guests could browse, search and open details. | The owner wants a profile-like first impression and features felt after login; it also keeps the catalog from being scraped anonymously. Trade-off accepted: titles are not discoverable through public search engines. |
| D-36 | Update notice: admin content changes go live within 60 seconds without any notice. For code releases an open tab shows a non-blocking "new version available" toast with [Update] and [Later]. The page never reloads by itself. Old tabs keep working because assets and AJAX endpoints stay compatible for 14 days. Details: F-23, OPERATIONS.md. | The owner wants users to keep working and choose when to update. It refines D-29: nobody is forced to wait or reload. |
| D-37 | Failures that are not the user's fault show a specific, branded message with a next action: 404, 403, 419, 429, 500, 503, offline and failed requests. Admin URLs return the normal 404. Details: F-24, DESIGN_SYSTEM.md section 11. | Users should always understand what happened and what to do. |
| D-38 | Two AI chats. Global chat: opens as a panel from a navbar button (icon plus label "AI Chat"), a popover on 1024px+ and a full-height sheet on mobile; there is no separate `/ai` page. Title chat: a card inside the detail page, sized to the page's content box and never full screen (on mobile it is an inline section with its own scroll). Both are one component and share one daily quota. | Owner's design; the panel matches the reference mockup. |
| D-41 | Title chat scope: it answers any question the user asks (plot, cast, ending, trivia, scenes and clips, and also topics outside the title or outside movies), with the opened title loaded from the DB as the default context. Safety refusals still apply (sexual/explicit, piracy, harm). The global chat stays limited to movies and series. When the title chat opens it shows a default prompt "What would you like to know about {title}?" (UI text: no AI call, no quota). | Owner decision. Accepted trade-offs: more free-tier usage and a wider prompt-injection surface, handled by the guardrails in AI_BEHAVIOR.md section 6. |
| D-42 | Project setup (Phase 0, docs/SETUP.md) is done by the owner by hand before the first task. Agents never install packages and never open, print or edit `.env`; they ask the owner to do it. | A complete, verified project folder before any prompt; keeps keys out of model providers' hands and the package list controlled. |
| D-43 | Version and patching policy: use the newest stable release line that still receives security fixes: PHP 8.5.x (never lower; a PHP branch outside security support is forbidden), Laravel 13.x, MySQL 8.4 LTS, the latest Node LTS (24 now; 26 once it is promoted to LTS), Composer 2. `composer.lock` and `package-lock.json` are committed. Patch releases are applied within 14 days and critical advisories immediately, using the monthly routine in OPERATIONS.md section 16. `composer audit` and `npm audit` gate every deploy. Major upgrades are separate tasks, never mixed with feature work. | Older PHP branches lose security support (8.2 on 31 Dec 2026, 8.3 on 31 Dec 2027); the newest line lasts longest (PHP 8.5 security support until 31 Dec 2029). Locked and audited dependencies make upgrades safe. "Newest" means newest stable and supported, never a pre-release; the database stays on its LTS line. |
| D-44 | Plans: Free, Plus (Rp15.000 per month) and Pro (Rp28.000 per month), both paid plans under Rp30.000. Limits and prices live in settings (`plan.<free|plus|pro>.*`) and default to the table in FEATURES.md F-11. Plus means more searches; Pro means smarter searches (Smart model, critic step, more titles and clips, richer explanations, priority requests). "Smarter" may be advertised only while `ai:evaluate` shows Pro Smart beating the Standard model. | The site is a search and guidance tool, not a streaming service, so prices stay low; the plan table keeps every paid plan profitable (D-45). |
| D-45 | AI budget guard for paid plans: each paying user has an AI budget in rupiah per subscription period (defaults: Plus Rp6.000, Pro Rp11.300), about half of the plan's worst-case net revenue. Every AI call's estimated cost (tokens x model prices x a safety multiplier, plus the grounded-search fee) is added to the user's spend. At 60 percent a Pro user falls back from the Smart to the Standard model; at 80 percent AI web clip searches stop (saved clips and search links remain); at 100 percent AI pauses until the period renews. Prices, budgets and thresholds are settings. Free users have no rupiah budget: they use the no-billing key and the daily places of D-47. | AI cost per paying user cannot exceed about half of net revenue, even if the provider raises prices or a user uses everything. Budgets are in rupiah, so a price rise reduces volume, never margin. |
| D-46 | Payments go through Midtrans Snap (Midtrans only for the LSP; Xendit is a possible later addition). Auto-renew monthly is the primary option and is promoted on the pricing page: card (Visa, Mastercard, JCB) or GoPay through the Subscription API, with an explicit consent checkbox ("I authorize a monthly automatic charge of Rp... until I cancel"), a reminder email before each charge and two-click cancellation. Pay for 30 days (no auto-renew) is the alternative for methods that cannot be charged automatically: QRIS (OVO, DANA, LinkAja and bank apps), ShopeePay, GoPay, card, and bank transfer for Pro only. Convenience stores are not enabled. The price of a plan is the same for every method and is final: the user never pays an extra fee, and gateway fees are ours. An upgrade (Plus to Pro) starts immediately and is paid in full (the old plan's remaining days are forfeited and the checkout says so); a downgrade starts at the next renewal; no proration. Real charging stays off until D-13 is cleared. | The Subscription API supports only card and GoPay tokenization (checked in the official docs), so other methods can only be one-time payments. Bank transfer has a fixed fee that is too high for Rp15.000. Xendit supports auto-debit for more e-wallets (OVO, DANA, ShopeePay, LinkAja) but needs sales activation and provider approval, so it waits until after the LSP. |
| D-47 | Free AI runs on a Gemini key from a Google project WITHOUT billing (`GEMINI_API_KEY_FREE`), so it can never be charged. Google's free quota is one pool shared by all Free users, so access is rationed by daily places: the first AI message of the day takes one place (atomic); a user who holds a place keeps the full daily units until midnight (WIB); places are released in three waves (00:00, 08:00 and 16:00 WIB, settings) so users later in the day also get a chance. Places per day = `ai.free.pool_daily_limit` / `plan.free.daily_units` x `ai.free.overbook_pct` (default 100). When no places are left, a new user is told before typing, with the next wave time and a soft upgrade card. Free uses the cheapest Standard model, a shared answer cache for non-personal movie questions, and no AI web clip search (saved clips and the search link only). Plus and Pro use a separate billed key (`GEMINI_API_KEY_PAID`, billing enabled only after the first paying customer) and never use places. Bringing your own key (BYOK) is rejected. | Per-user isolation of Google's quota is impossible with one key; places make access predictable and fair, and paid users are never affected by the Free pool. Free costs Rp0 by construction. |
| D-48 | All UI text is formal, standard English in plain words: no contractions ("You have", not "You've"), no slang, short sentences, sentence case. A test scans the translation and view files for contractions. AI replies follow the user's language. Terms and Privacy pages are required. | Owner requirement: formal, clear and easy to understand. |
| D-49 | When AI is unavailable the user is told the real reason and the time it returns (four situations in AI_BEHAVIOR.md section 9). Upgrade prompts are soft cards in the accent color (never danger or warning), name a concrete benefit, offer "See plans" and "Maybe later", and use no countdowns, no "most popular" claims and no shaming. Features that need paid resources and are not live yet show a friendly "available at public launch" message through the F-21 mechanism, never an error and never as general "Coming soon" filler. | Honesty toward users and a pleasant, optional path to subscribing. |
| D-50 | New users are offered a short guided tour once: the first time a verified user reaches the logged-in home. The offer is recorded as seen when it is shown (per account, in the database), so it never appears again automatically, whatever the user chooses. Steps differ for Free, Plus and Pro and run on the home page and navbar only. The Account page has a user-initiated "Take the tour again" link; admins and a command can reset it for demos. | Owner requirement: once per account, across devices. |
| D-51 | Registration sends one verification email through the configured mail provider (we run no mail server). The link is signed and valid for 60 minutes; resending is throttled. Opening it in the same browser keeps the user logged in; in another browser the user must log in first (no auto-login from an email link, to prevent account pre-hijacking). Verification happens once per account; changing the email address requires verifying the new one. Unverified accounts older than 14 days are deleted by a scheduled command. The same provider sends password-reset, receipt, reminder and request emails, with no tracking pixels. | Proves email ownership safely and keeps personal data to a minimum. |
| D-52 | The real Gemini keys are configured at the very end (task T-43), guided step by step; the agent never reads `.env`. Until then `AI_DRIVER=fake` runs the whole chat flow with canned answers and a demo banner says so. `php artisan ai:check` reports key status, models, rate limits and whether grounding works, without printing the key. Gemini stays the provider and is replaced only if it becomes unworkable (checklist in INTEGRATIONS.md section 8). | Development does not depend on keys or cost; the owner stays in control of secrets. |
| D-53 | The product is built complete for the LSP: every feature works with sandbox payments and demo data. Going public is configuration, accounts and money, not coding (OPERATIONS.md section 18): TMDB commercial license, business registration, Midtrans production approval, paid AI key, hosting and domain. | Owner wants a ready-made product where only funding remains. |
